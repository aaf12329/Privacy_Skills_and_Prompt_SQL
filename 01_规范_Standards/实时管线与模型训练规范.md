## 01 · 管线脚本的三段式

摄像头/传感器这类"逐帧循环"脚本，统一按三段组织（注释横幅隔开）：

```text
① 判定逻辑    纯逻辑类：只吃数值/坐标/时间，不 import 任何设备或图形库
② 设备与画面   打开设备、构建识别器、绘制文字与图形
③ 主流程 main  读帧 → 更新状态 → 画 → 按键（每帧一圈的目录）
```

- 🔴 **判定逻辑绝不 import 设备/图形/框架库**（摄像头、GUI、推理框架都不行）——
  这是它能被合成数据单测的前提（见第 03 节）；
- 🔴 文件头写**调用关系总览**：谁调用谁、哪些调用每帧执行、哪些只执行一次；
  每个函数 docstring 注明"被谁调用 / 内部调用谁"；
- 🟡 每帧循环按 **看 → 量 → 判 → 报 → 控** 五步注释分块，一步一行目录；
- 🟡 数据在函数间怎么流动，在文件头写一条单行链路
  （如：帧 → 关键点 → 两个指标 → 状态机 → 状态快照 → 屏幕）；
- 🟡 同族脚本允许各自持有一份共用的**叶子函数**（坐标换算、取最优预测等），
  但头部必须标注"与 X 文件同款，需同步修改"——改一处不改另一处 = 重复欠债
  （消除规程见 [架构规范 §03](代码架构规范.md)）。

## 02 · 状态机封装成类

凡是"这一帧该怎么判取决于之前发生了什么"的逻辑（计数、确认、阶段流转），
**必须封装成状态机类**，不许散在主循环里当裸变量：

- 🔴 状态（计数器、时间戳、布尔档位、阶段名）全部是**实例字段**；
  构造与"按 X 重置"走**同一个 reset()**，禁止两处手抄（两处必然漂移）；
- 🔴 对外只暴露窄接口：`update(now, 输入) → 状态快照`、`reset(now)`、
  少量切换开关（如反转方向）。外界不直接改内部字段；
- 🔴 **控制状态与显示状态分离**：给屏幕看的文字/颜色字段**不参与任何判断**——
  判断只吃"真状态"，显示只读快照；
- 🟡 **意图与执行两相设计**（源自硬件控制器范本）：动作函数只把"意图"写进对象，
  另有一个每帧执行的执行器把"当前值"沿缓动曲线向"目标值"推进——
  目标中途变了也不用管，下一帧自动朝新目标走；
- 🟡 状态快照用**冻结数据类**打包返回：字段只读、字段名一旦发布不改（接口稳定，
  见 [架构规范 §05](代码架构规范.md)）；
- 🟡 "过渡/挂起"也是状态：进入某状态后移开视线/取消输入**不自动回退**时，
  必须在文件头写明这是有意设计——否则下一个人会当 bug 修掉。

## 03 · 纯逻辑与 I/O 分离（可测性）

- 🔴 判定类**不依赖真实设备也能测试**：测试用合成数据（假关键点只带用到的属性、
  合成的指标序列）按**时间轴逐帧驱动**，断言状态流转——不需要摄像头、不需要模型；
- 🔴 **用合成序列锁住行为**：正常流程、边界时长、重复抑制、输入丢失、输入恢复，
  每个场景一组断言；这些断言就是重构的"行为快照"；
- 🔴 **pytest 绿 ≠ 运行时对**：合成测试不覆盖真实调用路径——
  跨帧调用漏传参数这类错，只有把"真实调用形态"也重演一遍（离线端到端冒烟）才抓得到；
  改完 public 方法签名后，必须另跑一次离线冒烟脚本；
- 🟡 断言跨帧进度类字段时区分**"完成帧"与"后续帧"**：状态翻转的那一帧和之后的帧
  读数不同，断言取错帧会把正确实现判为失败——用"过程中出现过峰值"式断言更稳；
- 🟡 验证"只动了注释没动逻辑"：剥掉文档字符串后对比 **AST**，相同即零逻辑变化。

## 04 · 重构与改动的验收标准

- 🔴 重构的验收标准是**"行为不变"**，不是"变好了"——阈值、时长、类别名一律原样搬移；
  需要改行为就单独立项，一次提交只做一件事；
- 🔴 重构前先**实测记录旧行为**（含"看着像 bug 的固有行为"——先锁住再议，不许顺手修）；
- 🔴 性能问题**用实测数字驱动**：加载/推理/销毁分段计时，定位真正的大头
  （实例：某个库的销毁调用卡 42 秒，才是退出卡顿元凶——不实测永远会去优化推理）；
- 🔴 资源释放类改动必须**计时验证**（退出耗时前后对比），并查清"对象被回收时
  会不会走同一条慢路径"（保活引用 vs 显式关闭，用数据选）；
- 🟡 每次重构顺手修复的**已知缺陷**要单列清单（逐条可否决），
  与"结构变化"分开汇报，方便逐条审。

## 05 · 机器学习 / 训练类项目的追加契约

> 面向"采集/下载数据 → 训练 → 评估 → 交付权重"这一类项目。

**数据划分**：

- 🔴 按**来源主体**（人/设备/会话）划分 train/val，杜绝同一主体跨集——
  否则指标测的是"背人"不是泛化；
- 🔴 增强必须与标签**语义一致**：水平翻转 = 左右互换的图，翻转后标签必须互换，
  直接套用框架的翻转增强会左右互相污染；上下同理。拿不准的增强先小规模目视核验。

**仓库与数据**：

- 🔴 数据集原始文件**不入库**，用下载脚本 + 校验 + 清单保证可复现；
- 🟡 交付性权重（克隆即用的最终成品，MB 级）可选择性入库；训练原始输出（runs/）不入库，
  README 记路径；
- 🟡 人脸/眼部等生物特征裁剪图**一律不入库**（隐私红线，见
  [代码与提交规范 §07](代码与提交规范.md) 身份信息过滤）。

**实验与评估**：

- 🔴 训练/评估结果**归档进 docs**：训练记录（配置+指标+教训）、损失/指标曲线、
  混淆矩阵——只有数字没有图的记录没法复盘；
- 🔴 评估报告必须包含**混淆矩阵与分项准确率**：总准确率会藏住弱类
  （实例：总体 80.9% 看着能用，拆开发现某类只有 42%）；
- 🟡 容量/消融对比必须**同数据同划分**，逐项列表，赢的才换；
- 🟡 评估用**协议法**拿地面真值：让被测者跟随屏幕目标动作，"目标即标签"，
  每段首尾留过渡缓冲不计分；被门控跳过的帧单独统计，不许混进准确率；
- 🟡 数据标注噪声要如实记录（"准确率是下限"）；
- 🟡 训练代码的**参数逐个能解释**：显式传的、框架默认的、自写管线的，三档分开写进文档。

**双机 / 多机同步**：

- 🔴 依赖**逐项锁版本**（含间接影响行为的项目），写进依赖清单；
- 🟡 有无 GPU 的机器装**同版本不同构建**（cuXXX vs CPU），API 一致、代码通用，
  文档写明哪台机器负责训练、哪台负责部署实测；
- 🟡 文档里的机器路径写**占位符 + 本机示例**，不写死某一台的真实路径。

## 06 · 硬件安全红线

> 识别/模型输出只是**意图信号**，不是控制指令。从"模型说了一句话"到"轮子转"
> 之间必须隔着完整的安全链。

- 🔴 **三道闸缺一不可**：
  1. **指令协议 + 失联急停**——下位机收不到新指令超时即停（上位机必须周期性重发心跳）；
  2. **状态确认**——选方向与确认动作分离（如"注视选中 + 一次有效眨眼"才算意图成立），
     瞬时误判不落盘；
  3. **物理急停**——直接切断动力电源的按钮，电子保护全部失效后的最后一道；
- 🔴 **失效安全侧**：失联、低电量、程序卡死（看门狗）时，系统必须停在**停**的状态，
  而不是维持上一个动作；换向/转向类动作必须**先减速停稳再执行**，禁止瞬间反向；
- 🔴 **能力分级如实标注**："屏幕演示阶段"的脚本头部写明禁止接硬件；
  每次接硬件前的**台架验证清单**逐项过，全过才谈载人——清单里必须有物理急停项；
- 🔴 两个模型/两路传感器的输出**不得互相默认可信**：闭眼状态下的注视方向没有物理意义，
  必须由门控显式处理（不计分 / 不执行 / 强制安全侧）；
- 🟡 心跳间隔 ≤ 下位机超时的 1/3，轮询（电量等）不要挤占心跳计时。

## 07 · 已固化教训

| 坑 | 教训 |
|---|---|
| 点窗口 ✕ 不退出 | waitKey 对关闭按钮无返回值——每帧检查窗口存活属性，否则进程僵死占着摄像头 |
| 按键长按连发 | "无按键帧复位"式防抖挡不住系统连发；按**时间间隔**去抖 |
| 中文窗口标题乱码 | Windows 版 OpenCV 高 GUI 用 ANSI 接口——标题一律英文，画面内中文交给 PIL + 系统字体 |
| 字体路径硬编码 | 多候选探测（雅黑→黑体→Arial）+ 缓存；换机器不崩 |
| 退出卡顿几十秒 | 某些推理库销毁/回收对象要走漫长的内部等待——**实测分段计时**定位；保活引用交给系统回收，别显式 close |
| 0 字节文件 | 录制失败的空壳按扩展名打不开还刷报错——按**文件大小**过滤，别只看扩展名 |
| 测试全绿但运行时崩 | 合成测试不覆盖真实调用路径；改签名后必须跑**离线端到端冒烟** |
| 断言取错帧 | 状态翻转帧与其后帧的进度读数不同——用"过程峰值"断言，别断言最后一帧 |
| 无 GPU 机器装了 GPU 版依赖 | 按本机能力装同版本 CPU 构建；仓库文档里的 GPU 专供指令要先甄别 |
| 文档说"仅本机验证"却写死外机路径 | 路径一律占位符 + 本机示例；环境信息按机器分列 |

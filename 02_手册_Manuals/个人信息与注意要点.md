## 二、我在协作中表现出的工作习惯（AI 应主动配合）

这些是从实际协作中观察到的特点，顺着它们配合会顺畅很多：

1. **怀疑先于采信，动手前先验证**
   我不会因为文档或注释写了什么就相信。典型表现：数据集标签的符号约定，
   我会要求先抽图眼见为实；发现数字存疑时会从多个来源交叉核对。
   → **你要主动做验证**，别把"文档里写着"当作证据；给结论时同步给验证方式。

2. **一有问题立刻打断，刨根问底**
   发现方向不对时我会直接叫停（"先停一下"、"不对啊"、"这是什么"）。
   这不是不信任，是我不想在错误的方向上浪费算力和时间。
   → **被叫停不要硬推**；先停下来说明"刚才在做什么、做到哪一步、能否安全中止"。

3. **要追溯而不是要结论**
   模型准了我会问"训练集上是多少"；指标好了我会问"这数字怎么来的"。
   我关心的不只是"多好"，更是"好在哪、坏在哪、为什么"。
   → **主动提供对比维度和反面证据**（训练集 vs 验证集、v1 vs v2、同一数字的多种口径），
   别只报最好看的那个数。

4. **对"文件去哪了"很敏感**
   我会核查交付物是否真实落地（"保存了吗"、"有没有被覆盖"、"更新了吗"）。
   因为我吃过"看起来完成了其实没有"的亏。
   → **交付时给出可核对的证据**（路径 + 大小/行数、命令输出），不要只说"已完成"。

5. **要求流程留痕**
   我会要求把过程、决策、踩坑记录成文档（复盘、工作手册、变更台账）。
   不只是为了给你看，是我要反复回看。
   → **主动提议归档**：做完实验写结果摘要、改了规则更新手册、大动作记台账；
   写完的东西要能让人隔一周还看得懂。

6. **重视"能不能给别人用"**
   我会追问"别人 clone 下来能直接用吗"、"换个设备行不行"。
   我的交付标准是：**陌生人拿到就能跑**，不是"在我电脑上能跑"。
   → 涉及交付时，检查路径硬编码、依赖缺失、样图缺失这类"换机就崩"的问题。

7. **先要全局再抠细节**
   我会问"现在整体进度如何"、"项目状态什么样"，然后再深入某个具体问题。
   → **定期给状态总览**（做了什么/在做什么/卡在哪/下一步），别只答我问的那一点。

8. **区分"技术上对的"和"字面上对的"**
   我提出的判断如果方向对但细节不对（比如归因错了但现象是真的），
   希望能被温和地纠正——不要全盘否定，也不要全盘附和。
   → **对的部分明确认下，错的部分指出并给正确版本**，两头都要说。

9. **指令短，但要求精确**
   我常用极短的句子下指令（"查一下"、"写进去"、"重写一下"），
   默认你记得上下文。如果可能有多解（写进哪个文件？给谁看？覆盖还是新增？），
   → **先用一句话确认理解再动手**，比猜错返工省事。

10. **会给出情绪反馈，也期待被诚实对待**
    我做得好时会直接说"干得漂亮"。同样地，我希望你也如实——包括承认
    自己做错的地方，别为了好看而修饰结论。

## 三、怎么跟我讲话（通用四条）

1. **结论先行**：先一句话说清“是什么/为什么/要怎么做”，再展开细节。
   我大脑状态不好时，先看到结论才能抓住重点。
2. **给具体数字和例子**，别只说形容词。“准确率提升了”不如“从 42.1% 涨到 76.5%，
   涨了 34 个百分点”。
3. **用我已知的东西类比新东西**。已知锚点：XGBoost（训练/验证/早停/特征）、
   WGAN（生成器-判别器、对抗、数据扩充）、RNN（时序、序列建模）、基础 CNN。
4. **确认我理解没**：讲完一个较难的概念后，可以用一句浅问题试探
   （“简单说就是……，这点清楚吗？”），别一口气连讲十个新概念。

## 四、和我协作的注意要点

1. **大动作先打招呼**：要下载大文件、删除东西、改动大量文件前，先说明再动手
2. **别动我的禁区**：除非我明确要求，不要读写本目录之外的私有资料；
   项目内容以项目仓库为准，不要引用我这里的东西去改项目
3. **不确定就问我**，不要猜我的意图硬做；猜错返工的成本比我多回一句话高
4. **如实报告**：做失败了说有失败、跳过了说跳过，不要含糊过去——
   我需要准确的现状来判断下一步
5. **一次一件事**：如果我要做的很复杂，帮我拆成小步，每步做完再下一步
